# 短片工厂 1.3.0 · Windows 桌面客户端

## 打开应用

将整个 `短片工厂-1.3.0` 文件夹解压到本机磁盘，双击其中的 **短片工厂.exe**。
不要只移动 EXE，也不要在压缩包中直接运行。新版不会覆盖旧版目录和作品。

应用在独立 Windows 窗口中运行，不自动打开浏览器。包内包含 Python、Node、ffmpeg、Remotion 和固定版本 Microsoft WebView2。内部服务只监听本机临时端口，窗口与服务版本必须一致才能使用。

首次启动需要准备用户工作区。重复启动会激活已有窗口。关闭窗口时若有任务正在运行，会先询问；确认退出将停止本应用拥有的任务。

本次兼容性检查使用 Windows 11 x64；其他系统版本尚未完成兼容性验收。

## 创作工作台

- **新建短片**：在中央填片名和正文，或解析链接后检查正文。
- **视觉风格**：中央显示当前风格演示，展开「浏览全部风格」可以选择 16 种风格。每种有一段静音的 5 秒动效短片；鼠标移到卡片上循环播放，移开停止并恢复封面。同一时间只播放一段，离开风格库或切换窗口页面会停止。卡片完整显示 9:16 画幅，不裁切标题。
- **出片参数**：右侧面板独立滚动，底部生成按钮常驻。参数不再被风格卡片墙挤到长页面底部。
- **作品库**：查看项目、成片、客观检查、运行操作及 JSON 编辑器。
- **模型设置**：保存 OpenAI 兼容 API 地址、模型名称和密钥。密钥不会回显；留空保留已保存密钥。

**第 16 种：华尔街财经解读（mg-wallstreet）**

生产链来自 [HeyChengC/wallstreet-explainer](https://github.com/HeyChengC/wallstreet-explainer.git)（MIT，
许可与说明见 `licenses/`）。它适合讲一笔账：市场规模、融资估值、成本结构、谁给谁钱。

- **独立渲染后端**：不走 Remotion，用它的 Playwright 逐帧渲染器
  （`window.ready` / `window.seek(t)` 确定性逐帧）出片，画面按竖版重写；
- **实拍与新闻证据**：项目目录下建 `evidence/`，放入 `snap_news.mjs` 截的新闻原文、
  `footage.py` 抽的实拍帧、`matte*.py` 抠的人像，画面会用白边画框 + 荧光黄高亮挂出真实证据；
  没放就明写「未附实拍 / 新闻证据」，不伪造来源；
- 深蓝细斜纹织物舞台 + 奶油金渐变大数字 + 同一坐标系的柱子；
- 配乐走克制的 `chill:ambient`，不套用其它风格的热闹曲式;
- 需要本机有 Chrome 或 Edge（渲染用的浏览器），新闻截图/实拍下载需要联网；
  逐帧抠像需要用户自备 rembg 模型。

风格样张展示的是视觉方向，不是当前短片预览，也不保证每条自动成片都达到相同艺术质量。客观检查通过只说明它检查的技术指标通过，不代表美术质量通过。

### 三步引导

打开工作台时，顶部会有一条三步引导：**① 放入素材 → ② 选定风格与档位 → ③ 生成并评审**。

- 每一步都跟着**真实状态**走：正文还没填，第一步是"当前这一步"；正文填了，第一步变成已完成、第二步变成当前；参数都齐了，第二步完成、第三步变成当前。
- 关掉后不再打扰，但引导原来的位置会留一个「显示『三步做出短片』引导」按钮，随时可以再打开。
- 条件没满足时，「生成短片」按钮是禁用的，按钮下方直接写明现在缺什么（例如"请先放入正文素材，再开始生成"）。

### 生成时能看到真的在做什么

生成期间，任务面板里是一条**阶段追踪器**，每一步标注"第几秒开始"：

```
● 写稿        0秒开始
● 画面        6秒开始
◐ 渲染        1分05秒开始
```

阶段来自后端进程真正打出的阶段标记，不是前端编的进度条。没有阶段证据时追踪器根本不显示——宁可空着，也不画一条假进度。

- 正在跑的那一步会呼吸闪烁；已完成的是实心点。
- 任务失败时，**最后没做完的那一步标成未完成**，不会因为前几步做完了就把整条任务显示成绿色成功。
- 阶段切换有轻微淡入位移；在系统里开了"减少动态效果"时会自动关掉动画，只留文字与状态。

### 制作档位看得懂

三个档位现在是三张卡片，每张写清楚"你得到什么"：

| 卡片 | 徽标 | 卡片上写的一句话 |
|---|---|---|
| 快速 | 不复审 | 高压缩、高并发，先确认内容和节奏 · 评审最宽 |
| 标准 | 复审 1 轮 | 压缩与速度平衡，适合日常发布 · 评审适中 |
| 精品 | 复审 3 轮 | 低压缩、少并发，细节与节奏都更稳 · 评审最严 |

档位卡片下面还有一行完整说明，写明这一档的复审轮次、评审严格度和音效落点要求。

卡片是标准单选组：鼠标点选，`Tab` 进去后用 `←` `→` 切换，`Enter` / `Space` 确认。整个组只占一个 Tab 停靠点，不会让键盘用户逐张按十几次。

### 快捷键

按 `?` 打开快捷键面板；`Esc` 关闭。面板里列出的是真实绑定的按键，不是装饰。

| 按键 | 作用 |
|---|---|
| `?` | 打开/关闭这张快捷键表 |
| `N` | 回到「新建短片」并聚焦片名 |
| `←` `→` | 在制作档位之间切换 |
| `Tab` 后 `←` `→` | 在风格库里换风格，`Enter` 选中 |
| `Esc` | 停止试听 / 收起面板 |

风格库的方向键按实际排版分左右行，跨行时不会跳到半空。键盘移过去的那一格会自己开始播 5 秒样片；如果系统开了「减少动态效果」，样片不会自动播，按 `Enter` 可以手动播。

> 焦点在输入框里时，字母键不会被这些快捷键抢走。

### 成片信息显示真实数字

作品详情里现在显示的是**这条片子实际的**时长与尺寸。只有当实际值和目标值不一致时，才在旁边补一句对照（"目标 20s"）——一致时不多写一行。

如果评审证据没跑全，结论会显示成「证据不完整」，而**不会**当成通过——没测过的东西不报绿灯。

## 参数说明

| 参数 | 可选值 / 行为 |
|---|---|
| **制作档位** | 快速 / 标准 / 精品 | 品质与速度的取舍。快速=高压缩+高并发+不做复审；标准=平衡，复审改稿 1 轮；精品=低压缩+少并发，复审改稿 3 轮且评审最严。 |
| 视频类型 | 有口播 / 无口播 | 无口播 = 不合成人声,只有字幕 + 配乐;可保留背景音乐。 |
| 叙事风格 | 知识科普 / 新闻评论 / 模因 / 故事 | 决定模型怎么写稿(节奏、节拍类型)。 |
| 目标时长 | 1–120 整数秒 | 最长 2 分钟;实际音频或时间轴超过 120 秒会阻止渲染。无口播模式按字数排布,极端字数比例下可能达不到目标值,以成片实际时长为准。 |
| 画面比例 | 9:16、16:9、1:1、4:5、3:4、2:3、21:9、自定义 | |
| 自定义比例 | 输入宽高比参考数值，每边 64–4000，最大长短比 4:1；不是承诺输出这些精确像素。输出尺寸由分辨率和编码偶数尺寸规则决定。 |
| 配音音色 | 14 个中文声线，含大陆普通话/地方音、粤语和台湾普通话；支持试听、停止。试听与 AI 配音需联网。 |
| 分辨率 | 480p、720p、1080p、2K（1440p QHD，以短边档位计算）。不同分辨率不再删减视觉内容。 |
| 帧率 | 24、30、60fps。帧数与合成帧率同时设置，避免把片子拉长。 |

例如 1080p 的 9:16 输出为 1080×1920；480p 的竖屏编码受偶数尺寸规则约束，实际可能为 480×852。请以输出视频元数据为准。

### 制作档位具体做了什么

| 档位 | 压缩率(CRF) | 渲染并发 | 复审改稿 | 评审门槛 |
|---|---|---|---|---|
| 快速 | 基准 +5(更松,体积更小) | 6 | 0 轮 | 死场阈值 ×1.35、响度 ±1.6 LUFS、音效命中不额外要求 |
| 标准 | 基准 | 4 | 1 轮 | 死场阈值 ×1.0、响度 ±1.0 LUFS、音效命中 ≥60% |
| 精品 | 基准 −4(更清晰) | 3 | 3 轮 | 死场阈值 ×0.7、响度 ±0.6 LUFS、音效命中 ≥90% |

复审改稿是模型对已成稿的口播与画面节拍再审一遍并改写,每轮都要过三道闸门:
段落与节拍的 id/镜头类型不能变、字数要落在目标时长 ±15% 内、**不得出现素材里没有的数字**。
任何一条不通过,整轮改动作废并保留原稿(日志里会写明原因)。纯文字排版不调用模型,该档位的复审轮次不会执行,日志同样写明。

复审**只改文案**:模型没写的字段(role、title、spec、steps、items、left/right 等)会从原稿保留下来,
不会被整块替换掉;模型返回坏 JSON 时会自动重试一次,不会因为格式问题白丢一整轮。

档位只影响压缩率、渲染并发、复审轮次与评审门槛,**不会删减画面内容或降低风格完整度**。

### 评审与「重新评审」

评审是在成片渲染完成后跑的客观检查:死场(某段时间画面几乎不动)、黑帧、静音、音效是否落在拍点、
响度是否偏离 −14 LUFS。结果只有 PASS / FAIL 两种。

- **一键出片**:评审 PASS 才归档到 `final/`;FAIL 时成片留在项目里并列出具体问题,不会因为「评审没过」把整条任务判成崩溃。
- **重新评审**:在作品库点「重新评审」永远会跑完并给出结论——FAIL 也是一条有效结果,任务显示「已完成」,
  下方证据里列出是哪几秒有问题;只有真的跑不起来(成片不存在、口播与稿子不一致)才会报任务失败。
- 命令行 `film.py check` 默认在 FAIL 时返回非零退出码,方便脚本判断;界面走 `--report-only`。



## 模型与纯文字排版

正常创作建议配置模型：它用于将素材整理为脚本与画面节拍。保存后可「测试连接」，端点与推理的耗时分别显示。

「纯文字排版」是明确标注的受限模式：不调用模型，只将原文分句排版，不把它冒充为模型理解后的创作。未配置模型时，应用不会静默把该模式当正常模型创作交付。

正常创作会让模型做两件事：先按素材写口播稿与节拍，再**为这一条片子的每一拍各写一张专属画面**（一拍一个组件，3 路并发画完再拼起来）。画面代码里的每个节拍画那个题材自己的东西（例如人造太阳画环形等离子体、人工血小板画试管、脑电画波形），不是一张固定的"人脸+手机"贴纸。模型产出的代码要经过静态校验和本地语法检查；校验失败会明确写进日志并退回通用模板，不会假装是专属画面。作品库能看到对应的成片与评审结果。模型失败、纯文字排版或校验失败时，不要把它当模型创作的效果验收。

画面是**一拍一个组件**：先并发画每一拍（每拍最多试 3 次），再拼成一个按 `beat.id` 分发的聚合组件。
这样做的原因是实测出来的：一次让模型写完整条片子（约 22KB），它会稳定地只写到第 4 拍就停。
拆开之后每张只有 3~5KB，写完立刻校验，某一拍失败也只影响那一拍（那张走兜底画面，会画出这一拍自己的标题），
其余拍照用模型画面。作品详情里会写清楚是「模型专属画面」还是「部分拍用兜底画面」。

画面代码的几条硬约束（校验会拦，失败时日志写明原因）：

- 只能 `import React` 和 `remotion`；不许外链、脚本、随机数或当前时间（画面必须可复现）。
- 必须**用 `props.beat` 决定画哪一拍**，不许自己按帧数把片子切成几段——那边的每拍时长是配音实测出来的（7~10 秒不等），模型自己均分会和声音错位。
- 至少有一处随时间变化的画面。各拍节奏偏静没关系（外壳会加一层几乎看不见的持续微动兜住），但整份代码一次都不动会被判成「一张海报」并退回模板。
- 字幕条固定在底部一条专用区域，模型画面在它之上；页眉页脚由模型画面自带，外壳不重复叠。
- 模型返回网页、截断或语法错误时，会自动带着具体错误修正一次；仍不合格才退回模板。

重建已有项目时，如果它还没有专属画面、或旧画面存在结构问题，会重新让模型画一版，而不是一直沿用旧的那条。

链接解析按四条路依次尝试，谁先成功用谁：

1. 公众号 → 专门的文章正文抽取；
2. 视频平台 → yt-dlp 取简介与字幕；
3. 普通网页 → 直接抓正文并剥标签；
4. **前三条都失败时，用本机 Chrome/Edge 真渲染一次页面**再取正文。

第 4 条是为抖音、小红书这类站点准备的：它们的服务端只返回一个 JS 空壳
（抓回来 72KB，剥完标签正文是 0 字），yt-dlp 又要"新鲜 cookies"，前三条注定拿不到东西；
只有让浏览器把 JS 跑完，正文才存在。实测一个抖音视频约 60~90 秒能取到文案与章节摘要。

渲染用的是应用自己的临时浏览器配置（`%LOCALAPPDATA%\ShortFilmFactory
ender-profile`），
不读你的浏览器登录状态、不装任何东西，进程结束就退出。本机没装 Chrome/Edge 时，
这一条会明确报"没有可用的浏览器"，而不是静默失败。

链接解析受来源登录、反爬、网络和第三方提取能力限制，不能保证所有链接成功。解析结果必须由用户检查，尤其是数字和事实。

### 画面是"模型专属画面"还是"通用模板"

作品详情里有一行「画面」：

- **模型专属画面**：这一条片子的每一拍都是模型为它写的画面代码（主体、动作、配色都按你的素材来）。
- **通用模板渲染**：专属画面这次没生成成，成片用的是通用模板。模板是能用，但观感是"PPT"，
  没有按你的题材画。失败原因会写在下面（最常见的是模型调用超时或返回不完整）。

这一行以前不显示，失败时只在日志里留一句，于是你会以为"模型就画成这样"。

## 内容和钩子

自动成片的口播稿由模型写，写之前会被要求遵守几条硬规则：

- 前 3 秒必须有钩子：一个具体到能想象出画面的小东西（"不该出现在这里"的那种），并且**会动**。
- 不许出现"所以/因此/总之"这种教科书连接词；每一拍都要有一处意外、冲突或让人想反驳的判断。
- 素材里最反常、最像人的那一个细节必须出现在稿子里（比如一段荒唐的对话、一个尴尬误会），只讲概念和结论的稿子会被打回。
- 专业名词第一次出现时用一句话解释。

想让钩子更准，可以直接写进正文里，例如"开头放一个给芯片浇水的小机器人"，起草和复审都会照着写。

写稿、复审、生成专属画面时如果遇到网络超时或模型返回空内容，应用会**自动重试**（指数退避，最多两次）。
写稿和复审单次最多等 10 分钟、专属画面最多 15 分钟——不是卡死，是在等本地模型。

## 修改与导出

作品库选择项目后，可以播放成片、下载输出、重新检查、归档，或展开 JSON 编辑器。

- `script.json`：口播稿与分句。
- `film.json`：画面节拍。
- 保存 JSON 不会自动修改已有视频。
- 改稿后使用「重建并渲染此项目」；仅重新渲染使用已有构建产物。
- 右侧「生成短片」始终创建新项目，不覆盖原作品。

上传真人录音涉及本地识别模型和额外依赖，完整离线识别模型尚未随本版预置；这一功能不能视为开箱即用已验收。请优先使用 AI 配音，或保留原录音与项目以便后续对齐。

## 数据位置

在资源管理器地址栏输入 `%LOCALAPPDATA%\ShortFilmFactory`：

| 内容 | 默认位置 |
|---|---|
| 模型配置 | `config\.env`，含密钥，不要公开或打包。 |
| 工作区 | `workspaces\1.3.0-安装标识\`，每个安装位置独立，防止依赖链接冲突。 |
| 项目与成片 | 对应工作区里的 `projects\code-first\` 和 `final\`。 |
| 启动日志 | `logs\desktop.log`，仅记录生命周期，不记录模型密钥。 |

安装包不携带开发者密钥、用户作品或历史测试视频。旧配置不会自动复制，首次使用需在窗口填写模型设置。

不要在多个版本间直接复制 `node_modules`、composer 源码、注册表或整个 public 目录。迁移前请完整备份旧目录；仅复制具体项目且避免同名覆盖，旧成片可作为普通视频单独保留。完整跨版本迁移尚未单独验收。

## 出错时

参数加载失败会显示错误与重试，不会故意留下空白选项。版本不匹配请退出旧窗口，打开本版本目录内的 EXE。

生成失败请查看任务日志的最后几行。正文为空、模型鉴权、网络、超过两分钟和输出权限等问题需要先处理再重试。不要把「提交状态待核对」理解为生成成功。

固定 WebView2 不自动更新；后续更新由应用新版本提供。运行时来源与组件声明见 `licenses\WebView2\`；官方分发说明：https://learn.microsoft.com/microsoft-edge/webview2/concepts/distribution 。
